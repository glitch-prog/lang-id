# Этап 1. Постановка задачи

Статус: рабочий проект для обсуждения с руководителем. Требования ниже задают цели будущей системы; результаты обучения и измерений пока не получены.

## 1. Тема и границы работы

Предлагаемая формулировка темы: **«Определение языка пользовательских постов для мультиязычной модерации с анализом качества на близких языках»**.

Программа определяет язык текста и может использоваться как компонент системы модерации: например, для направления сообщения модератору, владеющему нужным языком. Самостоятельная оценка токсичности, удаление сообщений и перевод в задачу не входят.

Объект исследования — короткие пользовательские тексты. Предмет исследования — методы автоматического определения языка по тексту.

Цель работы — разработать и экспериментально оценить систему определения языка коротких текстов на основе классического машинного обучения, отдельно исследовав различение русского, украинского и белорусского языков.

Русский, украинский и белорусский рассматриваются как самостоятельные языки. Определение диалектов и стиля в эту рабочую постановку не входит: для него потребовались бы отдельные классы и размеченные примеры. Изменение исходной формулировки темы необходимо согласовать с руководителем.

## 2. Поддерживаемые языки

Для первой полной версии предлагается ограничиться десятью языками:

| Код ISO 639-1 | Язык |
|---|---|
| ru | Русский |
| uk | Украинский |
| be | Белорусский |
| en | Английский |
| de | Немецкий |
| fr | Французский |
| es | Испанский |
| pt | Португальский |
| pl | Польский |
| bg | Болгарский |

Это предложение по объёму работы, а не утверждённый список. Такой набор включает обязательную для выбранного эксперимента группу ru/uk/be и позволяет сравнить её с другими языками.

В имеющихся CSV нет uk и be. До обучения итоговой версии необходимо получить размеченные примеры этих языков. На этапе подготовки данных также следует добавить сопоставимые русские примеры из того же источника, чтобы снизить влияние различий между источниками. Исходные данные сохраняются отдельно от подготовленных выборок.

## 3. Входные и выходные данные

Вход — одна строка текста Unicode. После удаления пробелов по краям допустимая длина составляет от 1 до 1000 символов включительно. Под символом здесь понимается элемент строки Python, измеряемый через `len()`. Строка должна содержать хотя бы одну букву.

Выход для допустимого ввода:

- `lang` — код наиболее вероятного языка из поддерживаемого набора;
- `confidence` — оценка вероятности выбранного класса, число от 0 до 1;
- `top3` — три разных языка с наибольшими оценками, по убыванию.

Первый элемент `top3` совпадает с `lang` и `confidence`. Сумма оценок по всем поддерживаемым языкам приблизительно равна 1; сумма только трёх показанных оценок может быть меньше 1.

Пример контракта ответа; числа условные и не являются результатом работы модели:

```json
{
  "lang": "uk",
  "confidence": 0.82,
  "top3": [
    {"lang": "uk", "probability": 0.82},
    {"lang": "be", "probability": 0.10},
    {"lang": "ru", "probability": 0.05}
  ]
}
```

`confidence` отражает оценку модели. Значение 0.82 само по себе не доказывает, что 82% подобных ответов правильны: соответствие оценок реальной частоте ошибок требует отдельной проверки.

## 4. Функциональные требования

| ID | Требование | Как проверить |
|---|---|---|
| FR-01 | Принимать допустимую строку и возвращать один поддерживаемый код языка | Проверить вызов на обычных предложениях |
| FR-02 | Возвращать `confidence` и три лучших варианта в установленном формате | Проверить типы, диапазон значений, уникальность классов и сортировку |
| FR-03 | Отклонять пустую строку и строку из пробелов с понятной ошибкой | Передать `""` и `"   "` |
| FR-04 | Отклонять строку без букв, например из цифр или эмодзи | Передать `"12345"` и `"🙂🙂"` |
| FR-05 | Отклонять текст длиннее 1000 символов, не обрезая его молча | Сравнить поведение на строках длиной 1000 и 1001 символ |
| FR-06 | Обрабатывать текст с буквами, опечатками, URL, упоминаниями и эмодзи без аварийного завершения | Проверить заранее подготовленные примеры |
| FR-07 | Использовать одинаковую предобработку при обучении и применении модели | Проверить общий путь обработки текста |

Если позднее будет реализован API, эти правила станут контрактом его входной валидации. Сам API не является необходимой частью проверки модели на этом этапе.

## 5. Ограничения

- Задача — многоклассовая классификация с одним ответом: каждому тексту сопоставляется один язык.
- Для смешанного текста возвращается один наиболее вероятный класс. Разметка языка каждого фрагмента не выполняется.
- Языки вне списка автоматически и надёжно не распознаются как «неизвестные»: модель может отнести их к одному из известных классов даже с высокой оценкой.
- Очень короткий текст может не содержать достаточно информации для уверенного определения языка. Допустимость ввода не означает гарантированной правильности ответа.
- Качество на транслите, опечатках и смешанных текстах исследуется отдельно; равное качество с обычными текстами заранее не обещается.
- Учебные предложения и отзывы не полностью соответствуют реальным постам. Результат на таком датасете не следует автоматически переносить на все социальные сети.

## 6. Требования к качеству

Основная метрика — **macro-F1**: для каждого языка рассчитывается F1, затем берётся обычное среднее по языкам. Каждый язык получает одинаковый вес независимо от числа примеров.

Целевые значения из плана:

| Показатель | Цель |
|---|---:|
| Macro-F1 по всем поддерживаемым языкам | ≥ 0.95 |
| Среднее F1 для ru, uk и be | ≥ 0.85 |

Для группы ru/uk/be F1 каждого из трёх классов считается по полному набору тестовых предсказаний, после чего три значения усредняются. Ошибки между этими и остальными языками сохраняются в расчёте.

Дополнительно рассчитываются accuracy, precision/recall/F1 каждого языка, матрица ошибок и macro-F1 для текстов короче 20 символов. Для подгрупп указывается количество примеров и представленных языков. Если коротких текстов нет, метрика отмечается как недоступная.

Цели не являются уже достигнутыми результатами. Если модель не достигает цели, фиксируются фактические показатели и исследуются причины.

## 7. Нефункциональные требования

| ID | Требование | Условие измерения |
|---|---|---|
| NFR-01 | Работа на CPU | Обучение и предсказание доступны без GPU |
| NFR-02 | Отклик менее 50 мс | Рабочая трактовка: p95 времени обработки одного текста уже загруженной моделью |
| NFR-03 | Размер сохранённой модели менее 100 МБ | Размер всего файла Pipeline, включая векторизатор; для проверки принять 100 МБ = 100 000 000 байт |
| NFR-04 | Воспроизводимость эксперимента | Сохранены версии зависимостей, параметры, правило разбиения и `random_state=42` |

В измерение NFR-02 входят предобработка, преобразование текста, получение вероятностей и формирование топ-3. Загрузка модели, запуск приложения и сеть измеряются отдельно. После прогрева выполнить не менее 1000 одиночных запросов на зафиксированном наборе текстов разных длин и сохранить характеристики CPU, объём памяти и результаты по длинам текста. p95 — значение, которое не превышают 95% измерений. Эту трактовку требования по времени нужно согласовать с руководителем.

## 8. План проверки решения

1. Подготовить размеченные данные выбранных языков, проверить дубликаты и неоднозначную разметку.
2. Зафиксировать непересекающиеся train/valid/test в пропорции 70/15/15 со стратификацией. Одинаковые тексты не должны попадать в разные части.
3. Реализовать baseline самого частого класса и baseline на правилах.
4. Обучить Pipeline из символьного TF-IDF и логистической регрессии только на train.
5. Выбирать настройки по valid. Не использовать test для выбора модели, правил или параметров.
6. После фиксации решения оценить все сравниваемые варианты на test.
7. Сохранить метрики, матрицы ошибок, 10–15 разобранных ошибок, размер модели и измерения времени.

## 10. Как объяснить задачу своими словами

«Я делаю программу, которая по короткому тексту выбирает один из десяти языков. Она обучается на примерах, где язык уже известен. Отдельно проверю, как она различает русский, украинский и белорусский. Сравню обученную модель с двумя простыми решениями. Качество проверю на текстах, которые не использовались для обучения и подбора настроек. Программа будет возвращать язык и три наиболее вероятных варианта».
