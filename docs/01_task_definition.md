# Этап 1. Постановка задачи

Статус на 10 ноября 2026 года. Рабочая редакция по последнему письму преподавателя. Название темы, итоговый набор языков и целевые значения метрик предстоит согласовать.

## 1. Тема и границы работы

Предлагаемая тема — **«Определение языка и тональности пользовательских постов для мультиязычной модерации»**.

Цель работы — разработать и экспериментально оценить два классификатора коротких текстов на основе классического машинного обучения. Первый определяет язык поста для маршрутизации модератору, второй оценивает его тональность. За определение тональности отвечает одна общая многоязычная модель, которая получает исходный текст независимо от результата определения языка.

На втором уровне различаем положительную, нейтральную и отрицательную тональность. Диалектная классификация исключена из рабочего объёма после замечания преподавателя о том, что в рассмотренных корпусах постов несколько диалектов представлены только для арабского. Решения об удалении постов, определение токсичности и перевод находятся за рамками задачи.

## 2. Данные и классы

| Этап | Корпус | Что проверяем |
|---|---|---|
| Предварительный языковой эксперимент | Текущие CSV papluca, 90 000 строк на 20 языках до очистки | Воспроизводимость подготовки и качество определения языка по символьным n-граммам |
| Эксперименты на постах | Tweet Sentiment Multilingual (UMSAB), 24 240 твитов на 8 языках по карточке | Определение языка и тональности на целевом типе текстов |

Рабочий список языков для модели постов — `ar`, `de`, `en`, `es`, `fr`, `hi`, `it`, `pt`. Для UMSAB язык берётся из конфигурации корпуса, тональность — из метки записи. Пригодность корпуса и фактическое покрытие языков и тональностей проверяются при EDA и экспериментах на validation. Подробнее о данных в [обзоре корпусов](02_document_and_dataset_analysis.md).

## 3. Входные и выходные данные

Вход — одна строка текста Unicode. После удаления пробелов по краям допустимая длина составляет от 1 до 1000 символов включительно. Под символом здесь понимается элемент строки Python, измеряемый через `len()`. Строка должна содержать хотя бы одну букву.

Выход для допустимого ввода:

- `lang` — код наиболее вероятного языка из поддерживаемого набора;
- `confidence` — оценка вероятности выбранного класса, число от 0 до 1;
- `top3` — три разных языка с наибольшими оценками, по убыванию;
- `sentiment` — один из классов `negative`, `neutral`, `positive`;
- `sentiment_confidence` — оценка вероятности выбранной тональности, число от 0 до 1.

Первый элемент `top3` совпадает с `lang` и `confidence`. Сумма оценок по всем поддерживаемым языкам приблизительно равна 1; сумма только трёх показанных оценок может быть меньше 1.

В примере ответа приведены условные оценки.

```json
{
  "lang": "es",
  "confidence": 0.82,
  "top3": [
    {"lang": "es", "probability": 0.82},
    {"lang": "pt", "probability": 0.10},
    {"lang": "it", "probability": 0.05}
  ],
  "sentiment": "neutral",
  "sentiment_confidence": 0.64
}
```

`confidence` отражает оценку модели. Значение 0.82 само по себе не доказывает, что 82% подобных ответов правильны: соответствие оценок реальной частоте ошибок требует отдельной проверки.

## 4. Функциональные требования

| ID | Требование | Как проверить |
|---|---|---|
| FR-01 | Принимать допустимую строку и возвращать один поддерживаемый код языка | Проверить вызов на обычных предложениях |
| FR-02 | Возвращать `confidence` и три лучших варианта в установленном формате | Проверить типы, диапазон значений, уникальность классов и сортировку |
| FR-03 | Отклонять пустую строку и строку из пробелов с понятной ошибкой | Передать `""` и `"   "` |
| FR-04 | Отклонять строку без букв, например из цифр или эмодзи | Передать `"12345"` и `"🙂🙂"` |
| FR-05 | Отклонять текст длиннее 1000 символов, не обрезая его молча | Сравнить поведение на строках длиной 1000 и 1001 символ |
| FR-06 | Обрабатывать текст с буквами, опечатками, URL, упоминаниями и эмодзи без аварийного завершения | Проверить заранее подготовленные примеры |
| FR-07 | Использовать одинаковую предобработку при обучении и применении каждого классификатора | Проверить общий путь обработки текста для каждой модели |
| FR-08 | Возвращать класс тональности и его оценку | Проверить допустимые значения класса и диапазон оценки |

Если позднее будет реализован API, эти правила станут контрактом его входной валидации. Сам API не является необходимой частью проверки модели на этом этапе.

## 5. Ограничения

- Каждый классификатор возвращает один класс для текста целиком.
- Для смешанного текста языковой классификатор возвращает один наиболее вероятный язык для всего поста.
- Языки вне списка автоматически и надёжно не распознаются как «неизвестные»: модель может отнести их к одному из известных классов даже с высокой оценкой.
- Очень короткий текст может не содержать достаточно информации для уверенного определения языка. Допустимость ввода не означает гарантированной правильности ответа.
- Качество на транслите, опечатках и смешанных текстах исследуется отдельно; равное качество с обычными текстами заранее не обещается.
- Результаты на papluca относятся к отзывам и предложениям из корпуса. Качество на постах измеряется отдельно по твитам UMSAB.

## 6. Требования к качеству

Основная метрика для каждой задачи — **macro-F1**, среднее F1 по классам с одинаковым весом каждого класса. Показатели языка и тональности рассчитываются отдельно.

Для языка рабочий ориентир из исходного плана — macro-F1 ≥ 0,95. Применимость этого порога к твитам и целевое значение для тональности нужно согласовать до финального тестирования. Дополнительно считаются accuracy, precision/recall/F1 по классам и матрица ошибок.

Для определения языка отдельно считаем macro-F1 на текстах короче 20 символов и указываем объём и языковое покрытие подгруппы. Для тональности отдельно показываем macro-F1 по каждому языку UMSAB с числом примеров по классам. Если для среза нет данных, отмечаем это в отчёте.

## 7. Нефункциональные требования

| ID | Требование | Условие измерения |
|---|---|---|
| NFR-01 | Работа на CPU | Обучение и предсказание доступны без GPU |
| NFR-02 | Отклик менее 50 мс | Рабочий показатель — p95 времени обработки одного текста двумя уже загруженными моделями |
| NFR-03 | Размер сохранённых моделей менее 100 МБ | Суммарный размер сохранённых Pipeline, включая векторизаторы. Для проверки принимаем 100 МБ равными 100 000 000 байт |
| NFR-04 | Воспроизводимость эксперимента | Сохранены версии зависимостей, параметры, правило разбиения и `random_state=42` |

В измерение NFR-02 входят предобработка, получение обоих предсказаний, их вероятностей и формирование топ-3 языков. Загрузка модели, запуск приложения и сеть измеряются отдельно. После прогрева выполнить не менее 1000 одиночных запросов на зафиксированном наборе текстов разных длин и сохранить характеристики CPU, объём памяти и результаты по длинам текста. p95 — значение, которое не превышают 95% измерений. Эту трактовку требования по времени нужно согласовать с руководителем.

## 8. План работ

| Шаг | Действие | Результат |
|---|---|---|
| 1. Завершить EDA papluca | Продолжить с [проверки дубликатов и пересечений](03_eda_checklist.md#3-дубликаты-конфликты-меток-и-пересечения-выборок), затем проверить длины и примеры текстов. Зафиксировать очищенное разбиение train/valid/test | Воспроизводимый ноутбук и выборки без пересечений по группам текстов |
| 2. Запустить языковой эксперимент | Сравнить частый класс и правила по алфавиту с символьным TF-IDF + LogisticRegression. Начать с `char_wb` и диапазона `(1, 4)`, затем сравнить варианты n-грамм по valid | Первый результат по определению языка и таблица сравнения признаков |
| 3. Подготовить UMSAB | Зафиксировать версию корпуса, проверить объёмы по языкам и тональностям, дубликаты, конфликты меток и пересечения. Использовать одни и те же очищенные части для обеих задач | Паспорт корпуса и общее разбиение для экспериментов на постах |
| 4. Проверить обе задачи на твитах | Обучить языковой классификатор на восьми языках и общую модель тональности на трёх классах. Сравнить обе модели на validation с предсказанием самого частого класса своей задачи. Для тональности проверить пользу словесных n-грамм и сохранения эмодзи | Раздельные результаты и основание для решения, подходит ли корпус |
| 5. Провести финальную оценку | Зафиксировать настройки и цели, измерить качество на test, разобрать 10–15 ошибок, измерить задержку и размер моделей | Сравнение с baseline, разбор ошибок и материалы для записки и защиты |

Для каждой модели векторизатор и классификатор обучаются только на train. Настройки выбираются на valid. Test используется после фиксации моделей и метрик. Если официальные части очищаются или формируются заново, правило, размеры и баланс фиксируются в паспорте данных.

## 9. Что нужно согласовать

- Название темы с тональностью и рабочий список из восьми языков для постов.
- Целевые значения macro-F1 для языка и тональности на твитах.
- Объём демонстрации и трактовка ограничений по времени и размеру моделей для двух предсказаний.
