## 6. Предлагаемый объём курсовой

Рекомендация для обсуждения с руководителем:

1. **Язык:** восемь языков UMSAB — арабский, английский, французский, немецкий, хинди, итальянский, португальский, испанский. Это отклонение от ориентира 10–20 языков в плане; его следует явно согласовать, обосновав реальными постами и готовой разметкой.
2. **Диалект:** четыре варианта арабского из SHAMI. Для остальных языков диалект в этой версии не поддерживается. Так система остаётся мультиязычной, а диалектный уровень имеет реальные обучающие классы.
3. **Третий уровень:** тональность positive/neutral/negative на восьми языках. Она не равнозначна стилю, токсичности или основанию для удаления поста. Если руководитель требует именно стили «литературный/научный/сленг», понадобится другой корпус с такой разметкой.

Сценарий применения: определить язык поста и направить его подходящей группе модераторов; при поддерживаемом языке показать диалект и тональность как дополнительные признаки. Решение об удалении, определение токсичности и перевод не входят в этот предлагаемый объём.

Для задач не нужен единый корпус, где у каждой строки заполнены все три метки. Можно обучить три отдельных классификатора по соответствующим наборам. Отсутствующая диалектная разметка не означает «диалект отсутствует»: такие строки не используются как отрицательные примеры диалектного классификатора.

При таком составе данных можно оценить язык + диалект на SHAMI и язык + тональность на UMSAB. Для численной оценки одновременной правильности всех трёх ответов нужен отдельный тестовый набор, где у каждого поста присутствуют все три эталонные метки. Простая демонстрация трёх предсказаний такой оценкой не является.

Для языкового классификатора важно включить арабские диалектные тексты в его обучающие/проверочные данные, соблюдая общее разбиение. Иначе первый уровень может плохо распознавать именно те тексты, которые должен передавать второму. Один и тот же пост должен принадлежать одной части данных для всех уровней системы.

Возможный ответ прототипа:

```json
{
  "language": "ar",
  "language_confidence": 0.96,
  "dialect": "levantine_syrian",
  "dialect_status": "predicted",
  "dialect_confidence": 0.72,
  "sentiment": "neutral",
  "sentiment_confidence": 0.64
}
```

Числа условные. Название диалекта — внутренний идентификатор, а не код ISO 639-1. Для неподдерживаемого языка возвращаются `dialect: null` и `dialect_status: "unsupported_language"`. Случаи недостаточной уверенности нужно отличать от отсутствия поддержки; порог выбирается по validation и не гарантирует распознавание всех неизвестных диалектов.

## 7. Модели, оценка и ближайшие действия

Для каждого реализованного классификатора:

- Основная модель: символьные n-граммы → TF-IDF → LogisticRegression в Pipeline.
- Baseline: DummyClassifier; для языка дополнительно правила по алфавиту и частотным словам.
- Дополнительное сравнение: MultinomialNB и/или LinearSVC. Если необходимы вероятности, у LinearSVC требуется отдельная калибровка; оценки decision_function нельзя выдавать за вероятности.

Исходную настройку плана `char_wb`, `(1, 4)` можно использовать как стартовую; варианты признаков и гиперпараметры выбираются только по validation. Векторизатор обучается только на train. URL и упоминания можно заменять маркерами; решение по эмодзи проверять отдельно для языка и тональности. Удалять диалектные слова, стоп-слова и все особенности написания без проверки нежелательно.

Нужны macro-F1 для каждого уровня, accuracy и показатели классов; для языка дополнительно оценка по длине. Диалект проверяется отдельно при известном правильном языке и в полном каскаде с предсказанным языком. Тональность оценивается также по каждому языку. Общий процент правильных ответов не должен скрывать качество слабого уровня.

Числа 0,95 в целом и 0,85 на близких языках взяты из старого плана языковой задачи. Их нельзя автоматически переносить на арабские диалекты и тональность. Для новых задач целевые значения согласуются отдельно; требование должно быть определено до финального тестирования, результаты честно фиксируются даже при недостижении цели.

Данные SHAMI и UMSAB могут различаться по авторам, тематике и предобработке. По возможности разделять по авторам/тредам/источникам; минимум — исключить одинаковые и близкие тексты между частями. Для объединённых наборов нужен общий контроль пересечений, иначе обучение одного уровня может пересечься с тестом другого.

Следующая последовательность:

1. Передать руководителю результаты обзора и предложить 8 языков + 4 арабских диалекта + тональность.
2. Зафиксировать, допускаются ли диалекты одного языка и тональность вместо стиля; согласовать число языков.
3. Скачать выбранные текстовые корпуса, сохранить версии/даты/контрольные суммы и составить паспорт с фактическими объёмами после очистки.
4. Обновить постановку задачи, вход/выход и отдельные целевые метрики.
5. Подготовить разбиение без утечек, затем выполнять обучение и сравнение.
